# PANENKA — Pre-payment quality and release checklist

Scope: Existing .NET 10 MVC storefront and admin operations; **payment gateway connection excluded**.
Keep the store's existing page structure and database content. Never test a destructive operation against real customer orders.

## Automated checks in GitHub Actions

The workflow `.github/workflows/dotnet-ci.yml` restores and compiles the MVC/Razor project, then runs the tests under `tests/Paneka.Tests`.

- [x] Server-generated product/brand/collection/category slugs from names, uniqueness suffixes
- [x] Brands/collections ignore forged slug values in POST requests
- [x] Shop stock/size/price filtering against the database
- [x] Cart rejects inactive size/color variants on quantity update
- [x] Recommendations include only purchasable active variants
- [x] COD checkout creates order, reserves inventory, and does not duplicate an order for a repeated token
- [x] Cancellation restores stock and records status/history once

These checks do not claim that every browser interaction passes; production SQL Server, authentication, upload storage, and live infrastructure still need acceptance testing.

## Manual acceptance checklist (staging environment)

Use separate customer/admin test accounts and test products with controlled stock. Run the tests on a staging copy of the database, and record screenshots/errors as evidence.

### Catalog and URL management

- [ ] Admin: create two products with identical names. Confirm unique automatic URLs and no slug input.
- [ ] Admin: rename an existing product. Confirm new URL generated; unchanged product retains existing URL.
- [ ] Admin: create duplicate category, brand, and collection names; confirm unique, autogenerated identifiers.
- [ ] Admin: edit all four entities and confirm images, status, description, and product assignments remain intact.
- [ ] Product list: search/pagination/status/category filters show the correct records.
- [ ] Product gallery: upload/reorder/set cover/remove photos; ensure no broken thumbnails.
- [ ] Variants: add size/color/price/SKU, mark inactive, edit stock; confirm storefront and cart reflect changes.
- [ ] Collections and homepage banners: verify storefront placement and links use current records.

### Customer browsing

- [ ] Home: hero, collections, featured/new-arrival products, search, favorites, and navigation work.
- [ ] Shop: category, size, minimum/maximum price, in-stock, sorting, chips, reset, paging all work individually and combined.
- [ ] Shop: refresh a filtered URL; verify filter state is retained.
- [ ] Shop: use mobile filter drawer, apply/reset, and keyboard navigation.
- [ ] Cards/quick view: correct image, product name, price, compare-at price, stock, size/color, and details link.
- [ ] Quick add: selecting a low-stock variant restricts quantity and updates bag count.
- [ ] Product details: gallery, variant image, dynamic price, quantity, add to bag, and reviews.
- [ ] Wishlist: add/remove from product, home, shop and saved-items page.

### Cart, checkout and orders (cash on delivery only)

- [ ] Cart: add a product; merge repeated additions; increase/decrease quantity; remove an item.
- [ ] Cart: prevent zero/negative quantity and purchases above available stock.
- [ ] Cart: show a clear warning when variant, size, color or product becomes unavailable.
- [ ] Cart: recommendations open real product details, not demo data.
- [ ] Coupons: apply valid, invalid, expired, limit-reached coupons; remove applied coupon and verify totals.
- [ ] Delivery: validate required inputs and Dhaka/outside Dhaka fees; verify total after coupon and shipping.
- [ ] Submit COD order once; confirm unique number, correct price snapshot, pending payment/shipment, reduced stock and cleared cart.
- [ ] Double-submit / browser refresh; confirm no duplicate orders or duplicate stock deduction.
- [ ] My Orders: show order, order items and status; unauthorized customer must not view another customer's order.
- [ ] Cancel eligible pending COD order; verify stock/coupon allowance restored only once.
- [ ] Admin fulfillment: confirm order, process, assign courier, ship, deliver; order/shipment statuses agree.
- [ ] Verify that unpaid advance/online orders cannot be shipped by using the shipment editor (without integrating gateways).

### Account, admin and design

- [ ] Registration/login/logout/remember-me, locked-out/disabled users, and admin role routing.
- [ ] Account edit and image upload; invalid image formats rejected; old user session does not reveal another user's checkout data.
- [ ] Address create/edit/default/delete, including access restrictions.
- [ ] Admin menus, profile link, search, mobile sidebar, tables, forms, inline error messages and destructive-action confirmations.
- [ ] Categories, brands, collections, sizes/colors, products, coupons, banners, reviews, customers, orders, shipments, and settings each display their authorized actions.
- [ ] Check desktop (1440px), laptop (1024px), tablet (768px), phone (390px), keyboard navigation and reduced-motion mode.
- [ ] Verify SQL Server upgrade on staging: `Update-Database` only if there are already unapplied migrations. This change set introduces **no schema migrations**.

## Deployment commands

From the correct local git repository:
```powershell
git switch main
git pull --ff-only origin main
```

If running Visual Studio Package Manager Console with the MVC project as Default Project:
```powershell
Update-Database
```

Back up the SQL Server database and any server-local `wwwroot/uploads` assets first. `.gitignore` protects new runtime files from being committed but does not delete files already tracked in Git. Gateway/payment implementation is intentionally deferred.
